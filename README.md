# 第一人称汉堡 / First-Person Burger

> 工作标题：《灶台江湖》
> 一个 3D 烹饪经营游戏原型。**全程灰盒**（几何体占位），只验证机制与手感，不做美术。

**当前进度：第六阶段 —— 采购阶段与食材价格波动。**
从"点土豆 → 切块入锅 → 看火候出锅"的物理玩法，一路做到带连击经济、库存与每日行情波动的营业日循环。

---

## 这是什么

一个"看火候"的节奏经营游戏。核心张力来自一句话：

> **火候条在跑，甜区很窄，你必须在正确的那一瞬间点下去。**

- 火候分**四档**：生食 / 完美 / 过火 / 焦糊
- 甜区宽度随**食材**与**灶台等级**动态收放 —— 灶台越高级越赚，但窗口越窄
- 连续完美出锅触发**连击倍率**（×1 → ×2 → ×3…封顶 ×10）
- **失误必亏**：任何出餐都扣食材成本，焦糊还要倒赔售价
- 每天开市食材价格**浮动 ±20%**，买贵了就是白干

## 快速开始

### 方式一：双击启动器（Windows）

双击项目根目录的 **`start-game.bat`**。它会自动定位游戏目录、探测 Node 运行时、在**独立窗口**中启动 Vite、等服务器真正响应后再打开浏览器。

> 服务器跑在一个标题为 `CookingGame-DevServer` 的独立窗口里，**关掉那个窗口即停止服务器**。
> 每次运行会覆写 `game/launcher.log`，卡住时看它就知道走到哪一步。
> 自检：`start-game.bat probe 5173` 只探测端口，输出 `ALIVE=0/1`，无副作用。

### 方式二：手动

```bash
cd game
npm install
npm run dev
```

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 烹饪循环（主） | `/cook.html` | 采购进货 → 四档位烹饪 → 连击经济 → HUD + Juice |
| 切土豆 | `/scene.html` | 纯物理：点土豆切块、点地面摆新土豆 |
| 逻辑灰盒 | `/` | 营业日状态机步进器（无 3D） |

构建校验（类型检查 + 打包）：

```bash
cd game && npm run build
```

## 玩法（cook.html）

1. **采购阶段**：看今日行情（涨红跌绿），决定买多少，扣金币。库存跨日保留。
2. **点食材入锅** → 火候条亮起，开始升温。
3. **火候条上的高亮区 = 甜区**。它随食材与灶台等级实时收放。
4. **在甜区内点锅** → 完美出餐：金光 + 金币飞入 + 震动 + 上行音效 + 连击倍率。
5. **连续完美** → 收益递增。**生食 / 过火 / 焦糊** → 连击归零，画面泛红 + 下行音。
6. **不点锅，烧穿 100** → 焦糊：黑晕 + 重震 + 顾客愤怒 + 倒赔钱。
7. **打烊 → 次日**：定价 → 升级 → 打烊 → 次日采购，闭环滚动。

### 四档位

| 档位 | 条件 | 收益 |
| --- | --- | --- |
| 生食 | 甜区下界之前 | 售价 ×0.2，连击归零 |
| 完美 | 甜区内 | 售价 × 连击倍率，连击 +1 |
| 过火 | 甜区上界之后、未到 100 | 收入 0，倒赔售价 ×0.5 |
| 焦糊 | 火候 ≥ 100（自动） | 收入 0，重罚售价 ×0.8，顾客愤怒 |

**任何出餐都会扣食材成本** → 失误必亏。

## 目录结构

```
start-game.bat              # 双击启动器（Windows）
docs/                       # 设计材料：GDD / 数值策划表 / 架构 / 性能红线
assets/                     # 架构图与核心循环图（SVG）
game/
  src/
    core/                   # 与游戏无关的通用基建
      EventBus.ts           #   类型安全事件总线
      StateMachine.ts       #   通用有限状态机
      Ticker.ts             #   统一 rAF 帧循环 + 固定步长
      ObjectPool.ts         #   通用对象池
    game/                   # 玩法层（不碰 3D）
      config.ts             #   ★ 数值唯一事实来源
      events.ts             #   事件名常量 + 载荷契约
      BusinessDayMachine.ts #   营业日状态机
      CookingSystem.ts      #   火候推进 + 四档位判定（不算钱）
      EconomySystem.ts      #   连击 / 售价 / 成本 / 罚金（纯计算器）
      MarketSystem.ts       #   每日价格波动 / 库存 / 破产保护（纯计算器）
      DayController.ts      #   ★ 唯一结算中枢
    render/                 # Three.js + cannon-es：场景 / 物理 / 粒子
    ui/                     # HUD / Juice（震动、泛红、金币飞入）
    audio/                  # WebAudio 程序化合成音效（无音频资源文件）
    smoke-cook.ts           # 无头冒烟测试（关键测试代码，进版本库）
```

## 架构约束（硬规则）

数据流严格单向：

```
物理输入 → 意图事件 → 玩法判定 → 中枢结算 → 结果事件 → 表现层
```

- `game/` 与 `core/` **不 import three / cannon-es** —— 状态机只被事件驱动，绝不接触 3D 网格
- 模块之间**不得直接互相调用**，一律经事件总线
- `CookingSystem` **不算钱**，只发 `dish:cooked`（携带档位 + 质量参数）
- **金币只能由 `DayController` 结算**，`coin:earned` 全项目仅一处发出点
- `render/` 只订阅事件改视觉，不判断游戏规则

## 验证

WebGL / WebAudio 无法无头验证，但**逻辑层可以**。`game/src/smoke-cook.ts` 直接驱动真实链路
（EventBus + BusinessDayMachine + CookingSystem + DayController + EconomySystem），
覆盖参数解算、四档位账目、连击递增与封顶、库存与采购成本、破产保护、价格浮动上下限、
以及**事件总线无死循环**。
