# Web 端 3D 游戏 · 性能红线与 60FPS 防卡顿规范

> 角色：代码审查专家 ｜ 阶段：顶层性能约束（给全团队的硬规矩）
> 目标：同屏大量顾客/食材/粒子时，稳定 60FPS、不崩、不漏内存。

---

## 1. 帧预算（先算账）

60FPS = **每帧 16.6ms**。分配如下，超了就掉帧：

| 阶段 | 预算 | 超支表现 |
| --- | --- | --- |
| 渲染（提交 + GPU） | 8.0ms | Draw call 多、过绘 |
| 逻辑 + 物理 | 4.0ms | GC 抖动、热路径 new 对象 |
| GC / 系统开销 | 4.6ms | 内存上涨、卡顿尖刺 |

掉到 **<50FPS 即告警**，<30FPS 视为不可接受的发布阻断项。

---

## 2. 硬红线（超过即打回）

| 指标 | 桌面端 | 移动端 | 说明 |
| --- | --- | --- | --- |
| Draw call / 帧 | ≤ 200 | ≤ 100 | 超了就合批 / 实例化 |
| 同屏三角面 | ≤ 50 万 | ≤ 20 万 | LOD + 剔除兜底 |
| 独立材质 | ≤ 50 | ≤ 30 | 优先合图集（texture atlas） |
| 活跃物理刚体 | ≤ 150 | ≤ 80 | 静态用碰撞代理，非活跃休眠 |
| 同屏粒子 | ≤ 500 | ≤ 200 | 用 InstancedMesh / GPU 粒子 |
| 单帧 GC 分配 | ≤ 1MB | ≤ 0.5MB | 热路径零闭包/数组分配 |
| 纹理显存 | ≤ 256MB | ≤ 128MB | KTX2/Basis 压缩必开 |
| 首屏资源 | ≤ 8MB 压缩 | ≤ 5MB | 分包 + 流式加载，启动 ≤3s |

---

## 3. 防卡顿规范（怎么做）

- **对象池**：食材、粒子、顾客、金币、飘字全部池化，禁止运行时随意 `new`/`destroy`。
- **固定步长物理**：用 accumulator 模式，渲染帧率与物理解耦；`dt` 夹紧上限 0.033s，防卡顿后"螺旋死亡"。
- **实例化**：重复物体（盘子、食材、粒子）统一 `InstancedMesh`，一次提交画一片。
- **剔除与 LOD**：视锥剔除必开；远处顾客/家具降模；遮挡剔除在场景复杂时启用。
- **纹理策略**：glTF 模型必 Draco 压缩，纹理必 KTX2/Basis + mipmap，按需懒加载，离场即释放。
- **内存释放**：卸载即 `dispose()` geometry / material / texture / render target；组件销毁时解绑事件，防泄漏。
- **主线程不阻塞**：资源解码、寻路、大数据算在 Web Worker；大模型用 Draco 流式。
- **AI 节流**：顾客决策不在每帧跑，按分组定时器（如每 200ms 一批）推进耐心与寻路。
- **HUD 动画**：只用 `transform` / `opacity`，禁止触发 layout/paint 的动画。

---

## 4. 禁止项（代码审查直接拦）

- 禁止在热循环（每帧/每物理步）里 `new` 对象、拼接字符串当 key。
- 禁止未 `dispose` 的纹理 / 几何 / 材质滞留显存。
- 禁止同步加载大文件阻塞主线程。
- 禁止把 Three.js 对象交给 React Reconciler 管理（3D 命令式）。
- 禁止用 `setInterval` 跑游戏循环；必须用 `requestAnimationFrame` + 固定步长。
- 禁止全局单例无限增长（顾客/特效列表必须有上限与回收）。

---

## 5. 监控与回归

- 内置浮窗：实时 FPS、帧时间、Draw call、显存、JS 堆（基于 `stats.js` 扩展）。
- 每版本跑 **30 分钟压测**：满顾客 + 满特效 + 随机事件，截图内存曲线，对比基线。
- 工具链：Chrome DevTools Performance、Spector.js（WebGL 抓帧）、Memory 面板查泄漏。
- 卡顿尖刺（>50ms 单帧）必须定位到具体调用，写入性能回归表，不"先上线再看"。

---

## 6. 性能验收清单（提测前自查）

- [ ] 满负载 30 分钟平均 ≥58FPS，无持续下跌
- [ ] 内存曲线平稳，无单调上涨
- [ ] 切场景后显存回落，无残留纹理
- [ ] 低端机（移动端）≥30FPS 可玩
- [ ] 首屏 ≤3s，无白屏长等待

> 红线不是建议，是门槛。任何一项超标，审查不通过。
